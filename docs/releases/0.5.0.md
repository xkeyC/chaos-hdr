# Chaos HDR 0.5.0 — shader HDR fallback

## What changed

Version 0.5.0 adds a second HDR engine and an **Engine** choice in the sidebar and
accessible controls. Existing profiles keep working; a profile without the new
values uses **Auto** and the **Standard** shader preset.

- **Auto** uses NVIDIA TrueHDR and switches to the shader engine when NGX cannot
  start, evaluation fails, the desktop GPU is not NVIDIA, or the display peak is
  outside 400–2,000 nits. A marker file written around RTX startup also catches a
  compositor crash during NGX initialization, which no exception handler can see.
- **RTX HDR only** keeps the previous failure behavior. **Shader only** never loads
  NGX.
- The shader engine has BT.2446 Method A and Highlight boost curves, six presets,
  Peak output, Exposure, Colour boost, Highlight and Shadow controls.
- An adaptive debanding filter runs in the shader engine and can optionally run
  before TrueHDR. Edge-aware sharpening is available to both engines and to
  sharpening without HDR.

The direct-buffer path, TrueHDR's input preparation and its default settings are
unchanged unless the new options are enabled.

## Verification

Checked on an RTX 4090 with driver 615.78.08 and KWin 6.8.0 on NixOS:

- Standalone GPU test: RTX HDR and SDR-only regressions pass. The shader output
  matches an independent C++ reference within 1 of 1023 code values for both
  curves. Auto falls back when the NGX feature library is missing and on an AMD
  Raphael iGPU (radeonsi), again within 1 code value.
- Nested KWin on a virtual output: engine switching, fallback, the startup marker,
  Retry RTX HDR, the display-peak rules and the controls.

## Limits

The shader engine is a conventional tone-mapping shader, not NVIDIA's model, and
will not match its result. GPU cost has not been measured. The picture has not been
assessed on a physical HDR display in a game by this verification, and running
the effect inside KWin on a non-NVIDIA GPU has not been tested.
